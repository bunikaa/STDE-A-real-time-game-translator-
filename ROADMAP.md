# Игровой переводчик — план разработки

Оверлей-переводчик текста из игр. Первая цель — Monster Prom (EN → RU).

**Двойная цель проекта:** рабочий инструмент + практический опыт с нейросетями.
Этапы, помеченные **[ML]**, дают опыт машинного обучения напрямую.

## Ключевые решения

| Что | Выбор | Почему |
|---|---|---|
| Python | **3.12** (не 3.14) | ML-библиотеки ещё не собраны под 3.14 |
| Захват экрана | `mss` | быстрый, простой |
| OCR | Windows.Media.Ocr (`winsdk`) | нейросеть, работает на CPU |
| Перевод | `transformers` + `Helsinki-NLP/opus-mt-en-ru` | видно токенизацию и инференс, а не чёрный ящик |
| Запасной перевод | Argos Translate | если установка torch не заладится |
| Оверлей | Tkinter → позже PySide6 | встроен, ноль установки |
| Сленг | глоссарий подстановок → позже дообучение | NMT-модели сленг не тянут |

**В конвейере две нейросети** — OCR (компьютерное зрение) и перевод
(seq2seq-трансформер). Работа с ними в реальном времени, борьба за
«качество против задержки» — это и есть ML-инжиниринг.

**Ограничение железа:** нет дискретной видеокарты (Intel UHD, 1 ГБ; 31 ГБ RAM).
Локальная LLM на CPU даст 5–20 сек на реплику — для игры неприемлемо.
Поэтому специализированные модели перевода вместо LLM.
Для экспериментов с обучением — **Google Colab** (бесплатная T4, 16 ГБ).

**Ограничение Windows:** exclusive fullscreen не даёт ни захватить экран,
ни показать окно поверх. Игра должна идти в borderless windowed.
Большинство современных игр «фуллскрин» = borderless, так что обычно всё работает.

## Этапы

Каждый этап заканчивается работающей программой. Не переходим дальше,
пока текущий не работает.

### Этап 0 — Фундамент
- [ ] Поставить Python 3.12 рядом с 3.14
- [ ] Создать venv, разобраться зачем он нужен
- [ ] `.gitignore`, первый коммит
- **Учишь:** venv, pip, git

### Этап 1 — Захват экрана
- [ ] `mss`: скриншот заданной области → файл
- [ ] Координаты области в константах
- **Учишь:** установка пакетов, работа с координатами
- **Готово когда:** запускаешь скрипт → появляется `capture.png` с областью диалога

### Этап 2 — OCR **[ML]**
- [ ] `winsdk`: картинка → текст в консоль
- [ ] Препроцессинг: увеличение ×2–3, бинаризация, инверсия
- [ ] Подобрать параметры под шрифт Monster Prom, записать что помогло
- **Учишь:** инференс модели компьютерного зрения; как подготовка входных
  данных меняет качество предсказания — фундаментальный урок ML
- **Готово когда:** текст из игры печатается в консоль без грубых ошибок

### Этап 3 — Оверлей
- [ ] Tkinter-окно: `-topmost`, `-alpha`, без рамки
- [ ] Показывает захардкоженный текст поверх игры
- **Учишь:** GUI, событийный цикл
- **Готово когда:** окно висит поверх игры и не мешает играть

### Этап 4 — Склейка (намеренно кривая)
- [ ] Соединить 1+2+3 в один цикл `while True`
- [ ] Убедиться, что интерфейс подвисает
- **Смысл:** почувствовать проблему до того, как решать её
- **Готово когда:** работает, но лагает — и ты понимаешь почему

### Этап 5 — Потоки и очереди
- [ ] Разнести захват / OCR / отрисовку по потокам
- [ ] Связать через `queue.Queue`
- **Учишь:** `threading`, `queue` — главный навык этого проекта
- **Готово когда:** окно двигается плавно, пока идёт OCR

### Этап 6 — Детект стабилизации текста
- [ ] Сравнивать кадр с предыдущим
- [ ] OCR только когда N кадров подряд одинаковые (~300 мс)
- **Смысл:** в Monster Prom текст печатается посимвольно и замирает —
  ловим момент, когда реплика допечаталась
- **Готово когда:** OCR срабатывает один раз на реплику, а не 30 раз в секунду

### Этап 7 — Перевод **[ML]**
- [ ] `transformers` + `Helsinki-NLP/opus-mt-en-ru`
- [ ] Разобрать конвейер по частям: текст → токенизатор → тензоры →
      модель → декодер → текст. Распечатать промежуточные значения
- [ ] Абстракция `Translator` с методом `translate()`
- **Учишь:** токенизация, тензоры, инференс seq2seq-трансформера;
  классы и интерфейсы
- **Готово когда:** в оверлее русский текст, и ты можешь объяснить,
  что происходит на каждом шаге

### Этап 8 — Кэш
- [ ] Словарь `хэш(текст) → перевод`
- [ ] Сохранение в JSON между запусками
- **Учишь:** словари, хэши, работа с файлами
- **Готово когда:** повторные реплики переводятся мгновенно

### Этап 9 — Тестовый набор и метрика **[ML]**
- [ ] Собрать 30–50 реплик из игры с эталонным переводом
- [ ] Скрипт, прогоняющий модель по набору
- [ ] Замерить: качество (BLEU или ручная оценка) и задержку
- **Учишь:** evaluation — половина работы ML-инженера. Без набора для
  замера любое «стало лучше» это ощущение, а не факт
- **Готово когда:** одна команда выдаёт цифры качества и скорости

### Этап 10 — Сравнение моделей **[ML]**
- [ ] Прогнать по набору: opus-mt, nllb-200-distilled-600M, Argos
- [ ] Свести в таблицу: качество / скорость / размер
- [ ] Выбрать победителя обоснованно
- **Учишь:** выбор модели под задачу — классическая ML-задача с
  компромиссом между качеством, скоростью и размером
- **Готово когда:** есть таблица и обоснованный выбор

### Этап 11 — Квантизация **[ML]**
- [ ] Конвертировать модель в CTranslate2, int8
- [ ] Замерить ускорение и потерю качества на своём наборе
- **Учишь:** оптимизация инференса — востребованный навык. Увидишь,
  как модель ужимается в 4 раза почти без потери качества
- **Готово когда:** знаешь цену ускорения в баллах качества

### Этап 12 — Глоссарий сленга
- [ ] Свой словарь замен до перевода
- [ ] Правила через регулярки
- [ ] Замерить прирост на тестовом наборе из этапа 9
- **Учишь:** регулярные выражения; проверка гипотезы измерением
- **Готово когда:** игровой сленг переводится осмысленно, и это видно в цифрах

### Этап 13 — Удобство
- [ ] Выбор области мышкой вместо констант
- [ ] Горячая клавиша вкл/выкл
- [ ] Конфиг-файл
- **Учишь:** конфиги, обработка ввода

## Ориентир

Для Unity-игр (Monster Prom — Unity) существует **XUnity.AutoTranslator** —
плагин, перехватывающий текст напрямую, без OCR. Смотреть как эталон качества.
Мы идём через OCR: универсальнее и на этом учатся.
